# KHIDMAT

Pakistan's Trusted Service Platform — a bilingual (English / Urdu) mobile-first prototype for finding local service providers (plumbers, electricians, AC technicians, tutors, beauticians, etc.) across Pakistan.

> ⚠️ **Prototype / demo only.** This is a single-page front-end prototype. Provider data displayed in search results is generated by Google's Gemini API and is **not real**. Phone numbers and contact buttons are illustrative — do not call them. There is no backend, real authentication, or persistent booking system yet. See [Status & roadmap](#status--roadmap) below.

## Features

- **Bilingual UI** — Roman Urdu / Urdu (RTL) / English, switchable at runtime.
- **Dark and light themes**, persisted to `localStorage`.
- **Phone-style mobile-first layout** (capped at 480px width).
- **Onboarding** — paste a free [Gemini API key](https://aistudio.google.com) once to enable AI features.
- **Mock auth flow** — login, signup, OTP screens (UI only; no backend).
- **Home screen** — natural-language request input (Roman Urdu / Urdu / English), photo-upload hint, quick-pick service chips, browse-categories grid.
- **City picker** — searchable dropdown of Pakistani cities with optional Gemini-powered fuzzy search.
- **AI-driven search** — extracts intent (service type, urgency, location) and generates a ranked list of providers via Gemini.
- **Price estimator** — fair-market price ranges per service category.
- **Booking flow** — slot picker, special instructions, confirmation screen with booking reference, persisted to `localStorage`.
- **Bookings list and profile screens.**
- **Installable PWA** — static `manifest.webmanifest`, theme color, and icons.

## Run locally

The project is plain static files — no build tooling required.

```bash
# From the repo root
python3 -m http.server 8080
# then visit http://localhost:8080
```

Any other static server (`npx serve`, `caddy file-server`, etc.) works equally well.

> Opening `index.html` directly via `file://` will work for most things but may break the manifest fetch and any future service-worker integration. Prefer running a local server.

## Configuration

On first launch the app prompts for a **Google Gemini API key** (free tier available at [aistudio.google.com](https://aistudio.google.com)). The key is stored in `localStorage` only — no key is committed to the repository.

> ⚠️ **Security note.** The API key is sent directly from the browser to `generativelanguage.googleapis.com`. This is acceptable for a personal prototype but should **not** be used in production — the key is visible in network logs and to anyone with access to the device. A backend proxy is the next major architectural step.

## How it works

1. **Intent extraction.** The user's free-text request (in Roman Urdu, Urdu, or English) plus the selected city are sent to Gemini, which returns a structured JSON intent (service category, urgency, time preference, requirements).
2. **Provider generation.** Gemini is asked to return a JSON array of plausible Pakistani service providers, including names, phone numbers, ratings, distances, and pricing.
3. **Ranking & rendering.** The client sorts by an LLM-supplied `score` and renders provider cards with quick-action buttons (Book, WhatsApp, Call, Map).
4. **Booking.** The user selects a time slot; the booking is given a `KHD-XXXXXX` reference and saved to `localStorage`.

## Status & roadmap

This prototype is intentionally front-end-only so the UX can be iterated quickly. The following items are **known gaps** and planned work — most are tracked in the design discussion but not yet implemented.

### Critical (blocks any real launch)

- [ ] **Replace AI-generated providers with a real database** of consenting, verified Pakistani service providers. The current behaviour can dial real third parties' numbers and is not safe to ship.
- [ ] **Backend proxy for the Gemini API** so the API key is never exposed in the browser.
- [ ] **Real authentication** (e.g. Firebase, Supabase, or Clerk with WhatsApp OTP). The current login/signup/OTP screens are UI-only.
- [ ] **Persist bookings server-side** so they survive `localStorage` being cleared, and so providers actually receive them.
- [ ] **Implement cancel / reschedule** to match the "Free cancellation" copy.

### High value

- [ ] Send uploaded photos to Gemini Vision for diagnosis (currently only a `[Photo attached]` text marker is added).
- [ ] Real geolocation via `navigator.geolocation` instead of LLM-fabricated distances.
- [ ] Date picker for bookings (currently hardcoded to "tomorrow").
- [ ] Reviews & ratings flow after a job is completed.
- [ ] Forgot-password / password-reset flow.
- [ ] Push notifications and reminders (the timeline UI already advertises them).

### Polish & accessibility

- [ ] Replace `<div onclick>` patterns with `<button>` for keyboard / screen-reader access.
- [ ] `aria-live` announcements for the search-progress status.
- [ ] Localise `toLocaleDateString` to match the active language.
- [ ] Tablet/desktop-friendly responsive layout (currently always 480px wide).

### Tooling

- [ ] Service worker for offline support.
- [ ] Linter + formatter (ESLint, Prettier).
- [ ] Unit tests for the intent-extraction prompt and parser.
- [ ] CI workflow.
